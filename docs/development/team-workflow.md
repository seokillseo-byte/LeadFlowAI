# Team Workflow

GitHub is the shared source of truth.

## Before coding

1. Read AGENTS.md.
2. Read the relevant product requirement.
3. Read architecture and UI blueprint.
4. Identify acceptance criteria.
5. Create or update a GitHub Issue.

## While coding

- Work on a focused branch.
- Keep changes small and reviewable.
- Update docs/blueprints when behavior changes.
- Never commit secrets.
- Add tests for meaningful business logic.

## Pull request

A PR must explain:
- what changed
- which issue it closes
- which blueprint/spec changed
- tests run
- known limitations
- screenshots for meaningful UI changes

## Definition of Done

A task is done only when code, tests, documentation and blueprint are aligned and CI passes.
